# 구현과 요구사항 추적

## 범위

사용자 인터뷰에서 한국 해역의 운영단계 바람·파랑 입력조건, 기존 공개/보유자료 수집·검증, 조건부 통계·극한 후보·사용자 검토, Python 실행을 선택했다. 후속 요청으로 GUI 입력·출력·옵션 선택과 공개 GitHub 연결을 추가했다.

공개 저장소에는 구현에 필요한 범위·기술 근거만 정리한다. 원문 인터뷰·개인 파일 경로·실제 현장 데이터·인증정보를 포함하지 않는다.

## 모듈

| 모듈 | 역할 |
|---|---|
| models | JSON 설정과 검증, 자료 메타데이터, DLC 템플릿 |
| data | CSV/NetCDF 로드, 좌표 선택, 단위 확인, UTC·방향 정규화, 파일 계보 |
| providers | 공식 소스 카탈로그, 대기/파랑 분리 월별 CDS 요청과 다운로드 |
| analysis | 자료 적합성 게이트, 비교지표, 조건부/결합/방향 통계, 연최대 극치·bootstrap, DLC 후보·검토 상태 |
| gui | Qt 입력·옵션·표·차트·검토·출력. 분석/다운로드는 QThread에서 수행 |
| export | Excel·CSV, HTML 보고서, 설정과 SHA256 manifest |
| cli | GUI 실행, 설정파일 분석, 합성 예제, 템플릿 |

## 제품 상태와 설계 상태

분석엔진은 실제 값을 임의로 채우는 방식보다 부족한 근거를 드러내도록 구성한다. 원자료의 시간 정의를 모델 출력 간격에서 추정하지 않으며 배포 격자에서 원래 모델 격자를 추정하지 않는다. 지점 대표성 검토의 근거도 별도로 입력해야 한다.

`DLC_candidates`의 `*_candidate_*` 열은 환경조건 후보이고 `adopted_*` 열은 사용자의 예비 채택 기록이다. 자료가 보류이거나 합성이거나 원문 매핑을 확인하지 않은 경우 예비 채택을 차단한다. `eligible`은 현재 사용자 설정의 screening 자료 기준을 통과한 상태로, 인증 적합성 판정이 아니다.

입력 변경 시 분석 결과 객체를 무효화한다. 작업 실행 중 설정이 변경되면 기존 설정으로 계산한 결과도 채택하지 않는다. 분석 옵션의 초기 값은 규정 수치가 아니며 검토 확정 체크와 분리한다.

## 명시적 후속 기술 과제

1. 실제 한국 시범 지점과 프로젝트 터빈·설계 정의를 입력하고 공식 자료의 가용성·대표성을 평가.
2. 프로젝트의 IEC/DNV 판본과 상세 DLC 원문을 확인해 규칙별 조항을 매핑.
3. 지점별 격자/시간·검증 오차·자료 충족률·유효 연수와 보정 여부의 근거 확정.
4. 태풍/비태풍 분리, 독립 사건, 시계열 동질성, 비정상성·극한모델 민감도 검토.
5. 필요 시 POT·결합 극치 모델·환경등고선·스펙트럼·난류/OEM 연계 추가. 구조응답과의 검증을 별도 수행.

## 검증

테스트는 시간 정의·평균시간 불일치, 세밀한 배포 격자의 오판 방지, 관측 부재의 잠정/보류 분기, 방향 원형 차이, 연간 자료 충족률, Gumbel 수치의 독립 계산, 신뢰구간 재현, NetCDF 좌표·단위, CSV 충돌, 표·보고서·체크섬 및 GUI 전체 흐름을 다룬다.

API 요청 계획의 스키마·월별 날짜·대기/파랑 분리는 로컬에서 검사한다. CDS 실제 다운로드는 사용자 토큰과 약관 동의가 필요한 외부 통합이며 자격증명 없이 완료됐다고 표시하지 않는다. 합성 자료의 GUI 실행은 소프트웨어 검증이지 실해역 모델 검증이 아니다.
